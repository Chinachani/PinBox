# 1.0.24：首次使用、自动部署与界面整理

本次是在 1.0.23 全流程审查修复的基础上完善安装和使用流程，不重建库存，不自动迁移数据。

## 首次使用

- 新用户选择「独立使用」或「多设备使用」。已有明确的模式、服务器和连接密钥设置继续保留，不强制重选。
- Android 独立使用采用本机 IndexedDB；Windows / Linux 成品程序默认本机 SQLite 服务，仅允许回环访问。已明确选择本机离线库的客户端不会被自动改回 SQLite。
- 多设备入口分为「连接已有仓库」和「部署新仓库」。后者提供真实安装步骤，不会通过匿名网页更改服务端模式或获取密钥。
- 连接测试不保存设置；实际连接需验证成功后应用。切换数据源不清空、不合并、不推送库存，待推送操作原样保留。
- 数据中心分开显示当前数据源、服务器连接、推送、拉取和在线操作核对。服务器在线模式禁用不必要的拉取，并说明原因。

## 部署和连接密钥

推荐在安装 Docker Engine 和 Compose 插件的主机上运行 `sh install.sh`，宿主机不需要 Python。

- 自动创建随机连接密钥，私有保存到 `.env`，升级与重启保留原值。
- 首次交互安装显示新密钥；非交互安装、日志、状态检查和 JSON 输出不显示密钥。
- `sh install.sh token show` 显式查看；`sh install.sh token reset --yes` 重置并重新创建服务。
- 安装器保留已有的环境变量密钥，或接管直接 Compose 部署的 `data/access.json` 密钥，不为接管管理而更换它。
- 修复普通 Docker 用户安装时 `.env` 被容器创建为 root 私有文件、后续 Compose 无法读取的问题。私有配置交还调用用户，权限仍为 `600`。
- 显式重置 `.env` 密钥时同步更新已有备用文件密钥，防止丢失 `.env` 后旧密钥重新生效。两文件写入不是一个原子事务；失败会停止，不宣称已完成，也不自动重启服务。管理员应修复配置后重试。
- Windows 发布包增加 `PinBoxAdmin.exe` 控制台管理工具；Linux 使用 `pinbox setup/status/token`。管理命令不会初始化或修改库存。

共享服务不再允许以“密钥为空”为由匿名访问库存。独立服务同时约束 HTTP、HTTPS 的监听地址，校验请求来源 IP 与 Host，防止意外外网绑定和 DNS 重绑定；损坏的认证配置拒绝访问，不降级到无认证。

## UI 调整

与 Gemini 3.8 Flash 共同审查并调整现有蓝灰工业风界面，没有换成另一套设计系统：

- 分类合并为工具栏内一个可搜索的下拉入口，删除手机上重复展示的横滑分类行。
- 长分类名截断显示但保留完整提示；分类浮层不被滚动容器裁切，支持键盘选择。
- 连接、同步、核对按用途分组，不再平铺为一排相似按钮。
- 首次引导采用两张清晰的选择卡片，连接密钥默认隐藏；关闭或切到后台后重新遮蔽。
- 修复导航选中样式被覆盖和 `[hidden]` 被布局样式覆盖的问题，检查 320px 手机宽度、桌面及深浅主题。

## 回归保护

- 数据源切换遇到记账、导入或同步中的写操作时拒绝执行；支持 Web Locks 的环境同时检查其他窗口。
- 请求的服务器地址与密钥来自同一份设置快照，避免另一个窗口改连接时向旧地址发送新密钥。
- 已关闭的引导忽略迟到的连接结果，不重新弹确认框或偷偷应用设置。
- 已有浏览器离线数据不会被当成自动隐藏桌面 SQLite 库存的理由；没有明确模式时先解释数据位置并让用户选择。
- PWA 预缓存包含新增引导脚本，断网启动仍可使用原本的离线库存。

验证覆盖 Python 库存及访问控制、Node 离线数据层、桌面/移动浏览器操作，以及真实 Docker 的首次安装、升级、密钥重置和业务数据不变检查。所有写入测试都使用临时目录和合成库存，未拿真实库存做增删测试。

发布前本地验证：123 项 Python 测试、27 项 Node 测试、66 项浏览器测试全部通过（共 216 项）；真实 Docker 安装器验证通过，npm audit 与锁定 Python 依赖的 pip-audit 均未发现已知漏洞。

## 升级注意

1. 升级前分别备份服务器库存、服务端私有配置及各客户端完整本地备份。不要卸载 App 或清空浏览器数据来升级。
2. 服务端和客户端都升级到 1.0.24；已有密钥继续有效，不必重新生成。
3. 以前未设密钥的共享服务会生成密钥，管理员查看后提供给可信客户端。连接失败时使用页面上的「设置连接」，不要清空库存。
4. 源码直接运行的默认模式为共享；只想本机使用时先执行 `python backend/main.py setup --mode standalone`。Docker 部署固定为共享模式。
5. 更改服务端模式后重新启动进程，使监听地址随之改变；客户端切换模式不会改变服务端网络开放范围。

## 明确边界

- 这是共享访问密钥，不是员工账号或按角色分权。持有者可读写库存，也可备份、恢复和清空数据。
- 本版没有把长期密钥塞进 URL、二维码或匿名领取接口；短期配对码不在此次实现范围。
- HTTP 不加密密钥和数据；推荐受信任 HTTPS。普通局域网 HTTP 快捷方式不等同于支持离线启动的 PWA。
- 不支持 Web Locks 的浏览器只能提供当前窗口的写入保护，避免在多窗口同时切换连接或同步。
- 移动浏览器视口测试不等于 Android 真机摄像头、厂商 WebView、权限和文件分享验收。
- 旧版公开历史中的 Android 签名暴露风险仍存在。为保持原 APK 升级兼容，未擅自换签名或重写 Git 历史。
