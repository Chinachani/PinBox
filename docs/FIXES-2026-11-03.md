# PinBox 1.0.22 全流程修复

对应 `AUDIT-2026-11-03.md` 的 25 项已复现缺陷。原审查报告保留修复前的证据；本文件说明实现、兼容性和验收边界，不将模拟器尺寸测试或桥接单元测试称为真机验收。

## 修复清单

| 原编号 | 实现 |
| --- | --- |
| F01 | 在线库存变动必须带操作号和数据集标识；客户端在 IndexedDB 独立存储待确认请求，响应丢失、刷新和重试复用同号。服务器在同一事务记账和保存回执。不同的新操作不能越过待确认请求；数据中心提供安全核对入口。旧数据集的操作禁止重放，可查询旧回执并人工确认归档。 |
| F02 | 本地恢复/清空与推送共用跨标签页互斥；不支持 Web Locks 或旧窗口绕过锁时，数据代次与操作号双重核验仍阻止旧响应删除新队列。拉取同时检查代次和队列。 |
| F03 | 扫码绑定起始模式和会话代次；切换方向、离开扫描页、停止摄像头和结束批次使未提交解析失效。拍照异步识别也检查会话。已经提交的记账不假装可以取消。 |
| F04 | 测试连接仅使用临时地址/令牌，不保存；点击“应用连接设置”明确确认并刷新整个页面。其他标签页收到配置变化也刷新，避免旧缓存写入新库。 |
| F05 | BOM 型号归一化只清理空白，保留小数点、连字符等有含义字符；`4.7K` 不再等同 `47K`。 |
| F06 | BOM 缺料建档数量明确为 0，提示需求不等于到货；收货须另行入库。 |
| F07 | 在线编辑仅提交实际变动字段并携带原值；后端在写事务中核对，冲突拒绝覆盖。单价快捷编辑、单件归位入口也提交基准。旧无基准修改请求被拒绝。 |
| F08 | 完整备份协议升级为版本 2，保留顶层导入凭据；兼容旧本地 `local_meta` 凭据。含未推送队列的本地备份不能直接覆盖服务器，以免忽略待办或再次重放。 |
| F09 | 实时通知刷新物料、分类、汇总、库位；有弹窗时延后，防止覆盖用户输入。启用令牌后以 15 秒可见页面轮询替代关闭的 WebSocket。 |
| F10 | 离线入库前统一文本去空格、编号大写、字段类型和长度上限；库位创建/编辑/批量归位同步校验。导入品牌原值不再因空格造成自冲突。 |
| F11 | 自动安全备份和清空/恢复处于同一 SQLite 保留写锁范围，其他写入不能落在备份与覆盖之间。 |
| F12 | BOM 支持短 C 编号；小数、负数、零和越界数量报行号；末尾封装不能冒充数量，歧义须加明确数量，如 `R1 10k 0603 x603`。 |
| F13 | 分类集合更新时校验选中分类；消失则回到全部分类和第一页。 |
| F14 | 库位、待归位及统计快捷入口清除无关搜索/分类/旧库位，当前库位条件明确显示。 |
| F15 | 删除末页最后一行后夹到合法页并重新加载，不再卡在不可翻页的空列表。 |
| F16 | 待推送角标在 IndexedDB 事务提交后更新，跨标签页广播；失败事务不发布假状态。 |
| F17 | 本地恢复预分配不冲突的流水 ID，以 `add` 拒绝覆盖；队列也检查 ID、操作号唯一性。 |
| F18 | 在线/离线业务时间统一北京时间，今天和近 N 天均以自然日零点为界；趋势图采用同一口径。 |
| F19 | 非空物料行缺编号或数量时拒绝整份导入并指出行，不再静默跳过或默认入库 1 件。空行不算业务记录。 |

| F23 | 用途推断的数值匹配增加边界，`150R` 不会命中 `0R`；所有自动推断带“未核验”标识，不修改既有人工整理的真实库存说明。 |
| F24 | 离线详情流水按时间、ID 双重降序后取最近 30 条。 |
| F25 | 分类及主导航使用原生按钮；弹窗设置对话框语义、焦点约束和关闭后焦点恢复；允许浏览器缩放。 |

## 流程补充

- 手机和桌面分类面板均可搜索，不必横向滑动几十个分类。
- “结束本次”退出自动出入库并停止摄像头；保留确认结果，不把仍在服务器执行的操作伪装成已取消。
- 初始加载失败显示持久错误和重试入口。数据中心说明本机库/服务器库区别，显示 PWA 离线能力状态。
- 待推送明细可检查，不提供不核对的“全部强制重放”。复杂的历史冲突仍须对照备份/服务器人工处理。
- Android 文件导出使用 Capacitor Filesystem 写入应用缓存，再交给系统分享/另存面板；取消分享不代表文件已保存到下载目录。
- 桌面/手机浏览器用标准下载；库存报表与完整 JSON 备份区分使用。

## 部署与依赖

- `scripts/deploy-219.py` 从已提交源码构建完整发布目录；构建完成才短暂停服，在停止写入后留存私有全目录备份和业务基线，再覆盖代码/配置、启动和核对。
- 部署保留原 `data`、`certs`；从不运行初始化重置、恢复或清空接口。核对物料/流水/库位/数据集/导入凭据及全部已跟踪文件摘要。
- Docker 同时使用 `.dockerignore` 和运行文件白名单 `COPY`，不会因忽略文件漏发而把真实数据库或证书烘入镜像。Compose 以只读方式挂载业务代码。
- 部署启用或保留 API 令牌；凭据及部署快照仅存 `.deployment/` 和服务器私有 `.env`，不提交 Git。浏览器/客户端须在数据中心配置令牌。HTTP 仍可被同网段窃听，建议在可信 HTTPS 下使用。
- npm 修复 glob/minimatch 构建依赖公告，保留 Capacitor 6 兼容性；原有 tar 兼容补丁继续受安装步骤检查。
- Python 运行依赖通过 `backend/requirements.lock` 锁定版本与哈希，基础镜像固定摘要；升级镜像内 pip/setuptools。
- CI 执行全部 Python/JS/浏览器回归、npm moderate 门禁、Python 运行依赖审计、完整 Docker 构建及鉴权冒烟，再构建三个平台的安装包。

## 升级注意

1. 先导出当前各客户端本地完整备份，尤其是未推送队列。不要为升级而清空浏览器数据或卸载旧 App。
2. 服务器和客户端升级到 1.0.22；旧客户端缺操作号的在线出入库请求、无字段基准的编辑会被新服务器拒绝，而不是继续不安全记账。
3. 在“管理与看板 → 桌面与系统 → 数据中心”输入地址和令牌；可先仅测试，再“应用连接设置”。
4. 有不确定的在线操作使用“核对在线操作”；离线队列冲突先检查明细、导出备份，不改操作号强行重放。
5. JSON 备份 2 可保留新成本字段；旧版本可能忽略新元数据，不建议用旧客户端恢复新备份。旧流水成本未知是正确标识，不代表数量丢失。

## 验收边界

回归代码在 `tests/test_full_audit.py`、`tests/local-api.test.cjs`、`tests/browser/audit.spec.cjs`；历史回归继续运行。测试一律隔离数据库。新增反例覆盖响应丢失、并发记账、恢复/同步竞争、字段冲突、跨来源鉴权、Excel 回导、分类/分页导航及原生导出桥接。

- npm/Python 公告审计不是完整操作系统或 APK 系统级漏洞审计；不宣称消除所有未知漏洞。用途摘要仍不能代替厂商数据手册。
