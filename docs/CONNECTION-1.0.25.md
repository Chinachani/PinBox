# 1.0.25：连接设置完整保存

这是对 1.0.24 最后一轮异常场景验收发现问题的修订，不覆盖已经发布的 1.0.24 安装包。

## 问题与修复

旧实现分别保存地址、连接密钥、使用模式。在浏览器存储配额不足、写入被拒绝时，前面的字段可能已经改变，后面的字段却未保存；内存状态还可能先于持久化状态改变，从而形成新地址与旧密钥的错误组合。

- 三个字段现在保存在一条 `wms-data-settings` 记录中，一次原子写入成功后才更新当前连接。
- 保存失败明确提示，原连接完整保持不变，不刷新、不清空浏览器数据，也不影响库存或待推送操作。
- 首次引导也采用同一次保存，不再在提交后另写可能失败的引导标记。
- 新窗口整体读取连接记录，不再分别拼接地址和密钥；其他窗口仍须等待正在进行的写入或同步结束后重新载入设置。
- 兼容旧版本的已有设置，无须重新输入地址或密钥。已有完整记录优先于旧版独立字段，避免旧字段残留影响当前连接。
- 完整记录损坏时暂停数据请求并回到使用方式引导，不偷偷使用陈旧密钥。修复连接设置不删除本机库存或队列。

## 回归场景

新增测试覆盖保存时抛出配额异常、失败后的实际请求地址和认证头、一次写入完成首次引导、旧配置兼容、跨窗口完整读取、无效配置拒绝，以及连接配置损坏后的离线库存恢复。浏览器测试同时覆盖桌面和手机视口。

本地完整回归通过：123 项 Python、32 项 Node、72 项浏览器测试，共 227 项；Capacitor 资源同步也已通过。

## 升级

客户端与服务器升级到 1.0.25。Android 覆盖安装，浏览器正常刷新，不要卸载 App 或清空站点数据。服务器的现有连接密钥和库存继续保留，不需要重置密钥。
