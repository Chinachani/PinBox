# 1.0.26：让界面高亮对应真实状态

## 原因

原先“开始独立使用”“应用连接设置”“推送离线变更”使用固定的蓝色主按钮样式。它们表示操作入口，却与当前模式的选中样式过于相似：即使连接没有变化、待推送为零，也一直突出显示，容易误以为模式切换没有生效。

本次保持既有蓝灰主题，不更改库存结构、连接密钥或同步协议。界面方案经过 Gemini 3.8 Flash 的只读评审。

## 修复

- 首次选择的两种使用方式采用同等权重，不默认突出“独立使用”；键盘焦点停在引导标题，不暗示已选择某个按钮。
- 已配置客户端仅给实际使用的卡片加细边框及“当前使用”标记。当前独立使用按钮不可重复提交，多设备卡片仍可打开连接管理。
- 本机 SQLite 的独立使用与远程共享服务器区分判断；无法确认使用方式时不虚构选中标记。
- 数据中心切换项用浅色背景和明确的“当前”文字表示实际读写位置，并同步辅助技术使用的 `aria-pressed` 状态。
- 应用按钮仅在连接确有未保存修改、地址有效且没有操作进行时启用并突出。撤销修改、保存失败、正在测试时不会误标为已经应用。
- 推送按钮随真实队列变化：空队列置灰；新操作进入队列后启用；失败时保留剩余队列；全部完成后恢复中性样式。
- 未应用连接修改、原生客户端未配置地址、队列读取失败或正在处理操作时暂停相应同步按钮。服务器在线模式与仍有待推送操作的本机库禁止拉取覆盖。
- 设置仅展开或连接仅测试时，当前卡片不会跟着变化；切换取消或失败仍显示原数据源。异步操作期间禁用重复提交。
- README 同步解释选中样式、按钮可用条件，以及“队列为空不等于两端库存相同”。

## 验证

本地完整回归通过：123 项 Python、32 项 Node、90 项浏览器测试，共 245 项。其中新增 18 项桌面 / 手机高亮回归，覆盖首次未选择、实际模式切换、取消或认证失败、未保存连接、空队列、推送冲突与成功、原生客户端缺少地址、队列读取失败等场景。

另检查桌面与 320px 窄屏、深浅主题的实际截图；npm 与 Python 锁定依赖审计未发现已知漏洞。所有写入测试使用隔离的临时数据库或浏览器数据，真实库存数据库校验值未改变。浏览器手机视口和桥接测试不等于 Android 真机完整验收。

## 升级

服务器与客户端升级到 1.0.26；Android 覆盖安装，网页正常刷新。不要卸载 App、清空站点数据或重置连接密钥。现有连接设置、服务器库存、本机库存和待推送队列继续保留。本次不自动推送、拉取或迁移库存。

部署及密钥管理命令见 [README](../README.md)，前一版的原子连接设置保存见 [1.0.25 说明](CONNECTION-1.0.25.md)。
